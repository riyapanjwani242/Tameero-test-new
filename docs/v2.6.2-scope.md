### Technical note — Windows CI E2E test kaise implement hoga
- **Base pehle se mojood hai:** workflow ka "Install smoke" step
  `tests/smoke-windows.ps1` chalata hai — silent install
  (`/VERYSILENT /SUPPRESSMSGBOXES /NORESTART`), bundled PHP,
  dashboard HTTP 200, dashboard se project create, site start,
  front page 200, one-click admin, stop, delete, uninstall. Naya
  kaam ISI script ko extend karna hai, nayi machinery nahi.
- **Store create + born-complete assert:** create ka blueprint
  Store hoga (demo ON). Mukammal hone ka intezar meta file /
  dashboard state se (deadline ke sath). Assert points CLI se
  lenge (installed PHP + setup-site verify wala rasta) — Woo
  active hai, 4 Woo pages hain, 8 products hain,
  `woocommerce_coming_soon=no` — scraping par inhisaar nahi.
  HTTP par `/` aur `/shop/` ke 200 bhi check honge.
- **Hang-simulation hook:** wdh.php mein ek **test-only** rukawat
  (env flag, masalan `WDH_TEST_STALL=<step>`) jo sirf CI mein set
  hogi — production mein flag nahi hota, koi asar nahi. CI mein
  step timeout test ke liye chhota rakha jayega (env override,
  masalan 20s) taake CI 180s na intezar kare; mechanism bilkul
  wahi hoga jo production mein 180s par chalega. Assert: job log
  mein FAILED line, dashboard par Failed state, phir dashboard
  se hi Delete recovery, phir saaf create kamyab.
- **Report/artifacts:** fail ho to job logs + dashboard log
  artifact ke tor par upload honge (`if: failure()`); pass/fail
  ginati script ki output mein saaf ayegi.
- **Release gate pehle se isi tartib mein hai:** Release step
  smoke ke BAAD ata hai — smoke fail = job fail = release step
  skip. Ye tartib barqarar rahe gi.
